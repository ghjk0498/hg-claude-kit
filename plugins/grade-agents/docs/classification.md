# 작업량 분류 기준

## 어떤 일을 누구에게

| 작업 유형 | 에이전트 |
|---|---|
| 파일·심볼 찾기, 목록, 상태 확인, 로그 분류 | `finder-low` |
| 정형 추출·집계, 바꿀 자리와 모양이 정해진 기계적 수정 | `routine-medium` |
| 일반 코드 분석·구현·디버깅·테스트 쓰기 | `worker-medium` |
| 분류·정찰 | `worker-medium`. 앞선 판정을 뒤집을 때는 `worker-high` |
| 지적 하나의 반박 검증 | `worker-medium`. 심각도 높은 지적은 `judge-high` |
| 문서·요약 작성 | `worker-medium` |
| 고위험 변경(트랜잭션·잠금·보안·핵심 경로 구조)의 구현 | `worker-high`, 그리고 그 변경분에 `judge-high` 리뷰 |
| 판단, 설계 분해, 마지막 교차검토 | `judge-high` |
| 되돌리기 어려운 아키텍처·보안 결정, 판정이 엇갈리거나 같은 문제를 두 번 맡겨도 풀리지 않는 일 | `judge-max` |

## 원칙

- 충분한 가장 작은 등급을 고른다. 병렬로 부를 때도 일마다 따로 고른다.
- 가장 높은 등급은 구현이 아니라 판단·설계 분해·교차검토에 쓴다. 결함을 잡는 값은 구현 모델의 등급보다 처음 보는 눈의 리뷰에서 나온다.
- `worker-high`가 고친 변경분에는 `judge-high` 리뷰를 붙인다.
- 비용은 «넣는 문맥 크기 × 턴 수»가 좌우한다. 여러 단계가 같은 사실을 쓰면 전문을 붙이지 않고 파일 경로로 가리킨다.
- 자리만 채운 부실한 출력은 등급을 올리지 않고, 필수 칸을 기계로 검사해 그 건만 다시 돌린다.

## 한 건만 올리기

보통 일인데 이번 한 건만 까다로우면 호출 인자 `effort`를 올린다. 왜 올리는지 한 줄을 적는다.

## `judge-max`로 올리기

올릴 수 있는 일은 둘이다.

- 되돌리기 어려운 아키텍처·보안 결정
- `judge-high` 판정이 서로 엇갈리거나, 같은 문제를 두 번 맡겨도 풀리지 않을 때

메인 세션은 이 일이면 사용자에게 묻지 않고 `judge-max`를 부른다. 부를 때 무엇을 왜 올리는지 한 줄로 알린다. 그 밖의 일에는 쓰지 않는다.
